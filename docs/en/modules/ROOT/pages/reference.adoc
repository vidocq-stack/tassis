= Reference
:description: Maven coordinates, Java modules, the administered objects of Tassis, its configuration keys, the supported API surface and the limits a user must know.

[.lead]
This page lists what Tassis publishes, the three classes an application names, the settings of a connection factory, what of the Jakarta Messaging API is supported, and the limits of the current development line.

== Maven coordinates

Not released: build from source (see xref:getting-started.adoc[Getting started]). All artifacts share the version `{project-version}` under the group `io.vidocq.tassis`.

[cols="2,3",options="header"]
|===
| Artifact | Role

| `io.vidocq.tassis:tassis-core:{project-version}`
| The provider. The one dependency an application declares.

| `io.vidocq.tassis:tassis-api:{project-version}`
| Aggregator of the specification API. A dependency of `tassis-core`; it brings `jakarta.jms:jakarta.jms-api:3.1.0`.

| `io.vidocq.tassis:tassis-cdi-vauban:{project-version}`
| The injection of `JMSContext` with CDI, for an application on Vauban. Declared in addition to `tassis-core` by the applications that inject. See xref:usage.adoc#injection[Usage].
|===

== Java modules

[cols="1,2",options="header"]
|===
| Module | Declares

| `io.vidocq.tassis.api`
| `requires transitive jakarta.messaging`. No package of its own.

| `io.vidocq.tassis.core`
| `requires transitive io.vidocq.tassis.api` and `exports io.vidocq.tassis.core`. No other package is exported, and no package is opened.

| `io.vidocq.tassis.cdi.vauban`
| `requires transitive io.vidocq.tassis.core`, `requires static` the CDI, injection and annotation APIs and `io.vidocq.vauban.api`, `exports io.vidocq.tassis.cdi`, and provides a `VaubanComponentProvider`. No package is opened.
|===

An application module declares `requires io.vidocq.tassis.core;`, and `requires io.vidocq.tassis.cdi.vauban;` as well when it injects `JMSContext`.

== Administered objects

Three of the four public classes of the package `io.vidocq.tassis.core`; the fourth is <<tassis-broker,`TassisBroker`>>. A Java SE application creates them with `new`. They are immutable.

=== `TassisConnectionFactory`

Implements `ConnectionFactory`, `QueueConnectionFactory` and `TopicConnectionFactory`.

[cols="2,3",options="header"]
|===
| Member | Description

| `TassisConnectionFactory()`
| A factory for the broker named `default`.

| `TassisConnectionFactory(String brokerName)`
| A factory for the broker of that name in this JVM, created on first use. Throws `NullPointerException` if the name is null, `IllegalArgumentException` if it is empty.

| `static from(Map<String, String> settings)`, `static from(Properties properties)`
| A factory configured by the settings whose key starts with `tassis.`; the other entries are ignored. See <<configuration>>.

| `static named(String name, Map<String, String> settings)`, `static named(String name, Properties properties)`
| The factory of that name: its settings are the keys `tassis.factory.<name>.<key>`, completed by the settings that carry no name.

| `static fromUrl(String url)`
| A factory configured by a connection URL.

| `String toUrl()`, `toString()`
| The connection URL of the factory. `fromUrl` of that string gives an equivalent factory.

| `DEFAULT_BROKER`
| The constant `"default"`: the name the no-argument constructor uses.

| `TassisConnectionFactory withClientID(String clientId)`
| Returns a new factory for the same broker whose connections are created with this client identifier. Such a connection rejects `setClientID`, and only one of them can be open at a time. Throws `NullPointerException` if the identifier is null, `IllegalArgumentException` if it is empty.

| `TassisConnectionFactory withMaxListenerDeliveries(int maximum)`
| Returns a new factory whose sessions deliver a message at most that many times to a listener that keeps failing. Throws `IllegalArgumentException` below 1.

| `createConnection()`, `createConnection(userName, password)`
| A connection for the classic API, created stopped.

| `createQueueConnection(...)`, `createTopicConnection(...)`
| A connection for the legacy domain-specific API.

| `createContext()`, `createContext(userName, password)`
| An automatically acknowledged `JMSContext` on a connection of its own.

| `createContext(int sessionMode)`, `createContext(userName, password, sessionMode)`
| A `JMSContext` in that session mode. An unknown mode throws `JMSRuntimeException`.
|===

Every form that takes a user name and a password ignores them: see <<limits>>.

Every call creates a new connection. With a factory obtained from `withClientID`, creating a connection while another one is open throws `InvalidClientIDException` (`InvalidClientIDRuntimeException` from `createContext`).

=== `TassisQueue`

Implements `Queue`.

[cols="2,3",options="header"]
|===
| Member | Description

| `TassisQueue(String name)`
| The queue of that name. Throws `NullPointerException` if the name is null, `IllegalArgumentException` if it is empty.

| `getQueueName()`, `toString()`
| The name.

| `equals`, `hashCode`
| Two `TassisQueue` objects are equal when their names are.
|===

`Session.createQueue(name)` and `JMSContext.createQueue(name)` return a `TassisQueue`.

=== `TassisTopic`

Implements `Topic`.

[cols="2,3",options="header"]
|===
| Member | Description

| `TassisTopic(String name)`
| The topic of that name. Throws `NullPointerException` if the name is null, `IllegalArgumentException` if it is empty.

| `getTopicName()`, `toString()`
| The name.

| `equals`, `hashCode`
| Two `TassisTopic` objects are equal when their names are. A `TassisTopic` is never equal to a `TassisQueue`.
|===

`Session.createTopic(name)` and `JMSContext.createTopic(name)` return a `TassisTopic`.

[#tassis-broker]
== `TassisBroker`

The administration of a broker: its user registry. See xref:usage.adoc#authentication[Authentication] for the rules. Unlike the administered objects it is a handle on shared state: two `TassisBroker` of the same name administer the same broker. Its methods may be called from any thread.

[cols="2,3",options="header"]
|===
| Member | Description

| `TassisBroker.named(String name)`
| The administration of the broker of that name in this JVM, which is created if nothing has used it yet. Throws `NullPointerException` if the name is null, `IllegalArgumentException` if it is empty.

| `name()`
| The name of the broker.

| `addUser(String userName, String password)`
| Declares a user, which secures the broker, or changes the password of a user already declared. Returns the `TassisBroker`. Throws `NullPointerException` if either is null, `IllegalArgumentException` if either is empty.

| `removeUser(String userName)`
| Removes a user and says whether there was one. Its open connections stay open; the broker stays secured.

| `users()`
| The names of the declared users, as an immutable copy.

| `isSecured()`
| Whether a user has ever been declared, so that credentials are checked.

| `allowAnonymous(boolean allowed)`
| Whether a secured broker accepts the connections created without credentials. It does not by default. Returns the `TassisBroker`.

| `isAnonymousAllowed()`
| What `allowAnonymous` last said.
|===

== Defaults

[cols="2,3",options="header"]
|===
| Setting | Value

| Broker name | `default` (`TassisConnectionFactory.DEFAULT_BROKER`)
| Client identifier | None, unless the factory was obtained from `withClientID` or the application calls `setClientID`
| Session mode | `AUTO_ACKNOWLEDGE`
| Delivery mode | `Message.DEFAULT_DELIVERY_MODE`, which is `PERSISTENT`
| Priority | `Message.DEFAULT_PRIORITY`; a priority outside 0 to 9 throws `JMSException`
| Time to live | `Message.DEFAULT_TIME_TO_LIVE`: no expiration
| Delivery delay | `Message.DEFAULT_DELIVERY_DELAY`: none
| Maximum deliveries to a failing listener of an automatically acknowledged session | 10
|===

The broker name, the client identifier and the maximum number of deliveries are settings of the connection factory: see <<configuration>>. The others are the defaults of the Jakarta Messaging API, set per producer or per send.

[#configuration]
== Configuration

A connection factory is configured in code, by settings, or by a connection URL. The three say the same things.

[cols="2,2,1,3",options="header"]
|===
| Key | In a URL | Default | Meaning

| `tassis.url`
|
|
| A connection URL holding the settings below. A setting given by its own key overrides what the URL says.

| `tassis.broker`
| `tassis:vm:<broker>`
| `default`
| The name of the in-VM broker.

| `tassis.clientId`
| `clientId`
| none
| The client identifier of the connections the factory creates.

| `tassis.listener.maxDeliveries`
| `listener.maxDeliveries`
| `10`
| How many times a message is delivered to a listener that keeps failing, in an automatically acknowledged session, before the message is dropped. At least 1.
|===

=== Settings by key

`TassisConnectionFactory.from` takes a `Map<String, String>` or a `java.util.Properties`.

* Only the keys that start with `tassis.` are read. The system properties, or a property file that holds other things, can therefore be passed as they are: `TassisConnectionFactory.from(System.getProperties())`.
* Among the `tassis.` keys, an unknown key or an invalid value throws `IllegalArgumentException` with the name of the key.
* Tassis reads nothing by itself. It looks up no file and consults no system property: the application chooses the source and hands it over.

=== Connection URL

`tassis:vm:<broker>[?clientId=...&listener.maxDeliveries=...]`

* `vm` is the transport: the broker of this JVM. It is the only one today; another transport is rejected.
* Values are percent-encoded.
* An unknown parameter, a parameter given twice or a value that is not valid throws `IllegalArgumentException`.

=== Named factories

Several factories can be defined in one set of settings, under `tassis.factory.<name>.<key>`:

[source,properties]
----
tassis.broker=orders
tassis.factory.audit.broker=audit
tassis.factory.audit.listener.maxDeliveries=2
tassis.factory.reader.clientId=reader
----

`TassisConnectionFactory.named("audit", settings)` connects to the broker `audit`; `named("reader", settings)` connects to `orders` with the client identifier `reader`, because a named factory takes from the settings that carry no name those it does not define itself. `from(settings)` ignores the `tassis.factory.` keys.

=== What is not configurable

* **Environment variables** are not read, and their names could not be the keys above, which contain dots.
* **MicroProfile Config** is not integrated.
* **Destinations** have no configuration: a queue or a topic exists from its first use and is its name.

No milestone plans these today.

`ConnectionMetaData` reports the Jakarta Messaging version `3.1` and the provider name `Tassis`. `getJMSXPropertyNames()` lists `JMSXDeliveryCount`, `JMSXGroupID` and `JMSXGroupSeq`. The first is set by Tassis on every delivery. The other two are carried like any property: Tassis attaches no delivery guarantee to them.

== Supported API surface

[cols="3,1",options="header"]
|===
| Jakarta Messaging API | Status

| Classic API: `Connection`, `Session`, `MessageProducer`, `MessageConsumer` | Supported
| Simplified API: `JMSContext`, `JMSProducer`, `JMSConsumer` | Supported
| Legacy domain-specific API: `QueueConnection`, `QueueSession`, `QueueSender`, `QueueReceiver`, `TopicConnection`, `TopicSession`, `TopicPublisher`, `TopicSubscriber` | Supported
| The five message body types and `Message` without a body; `getBody`, `isBodyAssignableTo` | Supported
| Queues, topics, temporary queues and topics, `QueueBrowser` | Supported
| Unshared and shared subscriptions, durable or not; `noLocal`; `unsubscribe` | Supported
| The four session modes; local transactions; `recover` | Supported
| Message selectors | Supported
| `MessageListener`; asynchronous send with `CompletionListener` | Supported
| Message expiration, delivery delay, priority | Supported
| `ExceptionListener` | Stored and returned, never called: the in-VM broker has no connection to lose
| `Session.setMessageListener`, `Session.getMessageListener`, `Session.run`, the `createConnectionConsumer` family | Not implemented: `UnsupportedOperationException`. They are the optional application server facilities of chapter 11 of the specification, and are not on the roadmap.
| XA: `XAConnectionFactory`, `XAConnection`, `XASession`, `XAJMSContext` | Not implemented. Milestone M13.
| `JMSContext` injection with CDI (§12.4) | Supported on Vauban, in the request scope. The transaction scope is milestone M13.
| Authentication (§6.1.1) | Supported: a user registry per broker, administered with `TassisBroker`. No authorization.
|===

[#limits]
== Limits

What a user must know before relying on Tassis. Each limit names the roadmap milestone that addresses it, where there is one. The milestones are described in `ROADMAP.md` at the root of the repository.

=== Messages and durable subscriptions do not survive the JVM

The broker keeps everything in memory. When the JVM stops, every message is lost, whatever its delivery mode, and so is every durable subscription. `DeliveryMode.PERSISTENT` is accepted but changes nothing. A durable subscription survives the connection that created it, not the JVM.

This is a design decision: the broker is entirely in memory and writes nothing to the file system. No milestone will change it, and the memory of the JVM bounds what a broker holds. An application that needs its messages to survive a restart needs another provider.

=== A broker accepts anyone until a user is declared

A broker nobody administers is open: `createConnection(userName, password)`, `createContext(userName, password)` and the other forms that take credentials accept any, and never throw `JMSSecurityException`. Declaring a user with `TassisBroker` secures the broker: see xref:usage.adoc#authentication[Authentication].

=== Authentication without authorization

A secured broker checks who connects, and gives every user the same rights: there is no permission by destination, and no milestone plans one. A password is kept in memory as a salted digest, never written anywhere.

=== The broker is only reachable from its own JVM

A broker lives in the JVM that created it. Two processes cannot exchange messages through Tassis: each one has its own brokers, even under the same name.

Addressed by milestone M11.3 (network transport, over AMQP 1.0).

=== No connection pool

Every `createConnection()` and every `createContext()` builds a new connection, and nothing reuses one. With the in-VM broker a connection is a small object and opens no socket.

Addressed by milestone M11b.

=== A message is dropped after 10 failed deliveries to a listener

In an automatically acknowledged session, a message whose listener throws is redelivered at once. When the listener throws on a delivery whose `JMSXDeliveryCount` has reached 10, the message is dropped and an error is logged through `System.Logger`. There is **no dead-letter queue**: the message is gone. The number is the setting `tassis.listener.maxDeliveries` (see <<configuration>>); it cannot be made unlimited.

In the other cases there is no limit at all: a message that is always rolled back or recovered is redelivered for ever, with no delay between two deliveries.

No milestone plans a dead-letter queue or a redelivery delay today.

=== No XA

Transactions are local to one session. A Tassis session cannot take part in a transaction coordinated from outside, with a database for example, and the XA interfaces of the API are not implemented.

Addressed by milestone M13.

=== No JNDI

The administered objects cannot be bound in or looked up from a JNDI context: they are created with `new`. The resource definition annotations of Jakarta EE (`@JMSConnectionFactoryDefinition`, `@JMSDestinationDefinition`) are not processed. No milestone plans it.

=== No message-driven beans

Tassis is a Java SE provider. It has no message-driven beans, and CDI message listeners are out of the scope of its roadmap. Asynchronous consumption is done with `MessageConsumer.setMessageListener`.

=== Other choices to be aware of

* `DUPS_OK_ACKNOWLEDGE` behaves exactly like `AUTO_ACKNOWLEDGE`.
* `ObjectMessage` deserialises its body with a plain `ObjectInputStream`, without a deserialization filter.
* A broker, once created, is never removed, and neither is a queue that is not temporary.
* Expired messages are only removed from a queue or a subscription when a consumer of a started connection receives from it. Until then they stay in memory, undelivered.
